# Managed gateway deployment

This deployment uses the pinned v1.106.0 model runtime with a separate PostgreSQL database and Redis instance. The public console uses the application's existing authorization server and server-held management credentials. Neither the native login form nor the model runtime's management port is a public entry point

Create a private `.env` in the deployment directory with independently generated `POSTGRES_PASSWORD`, `LITELLM_MASTER_KEY` and `LITELLM_SALT_KEY`. Preserve this file and the data directories for restart and restore. Do not change the salt key after storing provider credentials. Copy `compose.yml` and `litellm-config.yaml` to that directory, then run `docker-compose -p ai-gateway-e2e up -d`

The model runtime binds only to loopback port 18352. The authenticated application forwards permitted model requests and performs server-side authorization for every management action. Provider credentials and personal model keys must never reach the console's browser storage or model-visible tools

The E2E deployment does not replace a production service. Keep at least 15 GiB free before starting, restrict containers to the declared resource limits, and retain the previous application image and database backups. Raw traces, environment files and authentication state remain in private storage

Build the native dashboard with `NEXT_PUBLIC_MANAGED_GATEWAY=1 npm run build`. On Windows worktrees whose dependencies are a junction outside the project, use `npm run build -- --webpack`. Serve the complete `out` directory through the authenticated gateway using `MCP_CONSOLE_REACT_ROOT`. Business routes live under the existing dashboard layout, and the normal non-managed build retains the original native authentication behavior

The managed branch includes the complete Chinese dashboard from `litellm_zh_cn_v1_106_0` at `0f77a8ed7a3b1ff31522458764131f34622a4858`. Managed business labels use the same language context and locale dictionaries. Deploy this managed export in the business gateway image: replacing only the separate LiteLLM runtime image does not update the managed console. Keep the running business gateway as the image base and replace only its `MCP_CONSOLE_REACT_ROOT` export, preserving its server code, command, environment, mounts and authorization stores

Currency display and budget entry use a fixed rate of CNY 6.8 per USD from `aaf229a4882e60c1376d1506798e29e191d6e8e4`. The managed grants and workspace pages use the same conversion. Budget writes convert CNY back to USD, and stored amounts retain their existing USD contract

The budget-save repair makes the managed grants table, editor and workspace labels explicitly CNY in both languages. Cost indicators in chat, projects, policy templates, MCP pricing and guardrail monitoring use the matching yuan symbol. Its gateway companion preserves an existing user's delivery state during budget-only edits and tolerates native floating-point roundtrip differences. Ship the managed export and that narrowly merged gateway repair together

Verification for this repair includes 79 focused UI tests, typechecking, a managed webpack production build and a real browser save from 50 to 100 CNY against an isolated gateway with synthetic native responses and persistent SQLite. ESLint has no new errors. A broader translation check still reports the pre-existing `nativeLoad.configFetch` placeholder mismatch, which is unchanged by this repair. Production activation and post-activation browser acceptance remain separate from these checks

Central browser authentication uses a non-secret readiness marker for existing native UI hooks. All requests authenticate through the HttpOnly BFF cookie, strip bearer headers, attach CSRF on writes and reject other origins. Provider credentials, native management keys and personal model keys stay on the server. Native Playground Chat uses the explicitly granted personal key through the BFF; native user creation does not generate additional keys

The pinned runtime uses the supported `disable_aiohttp_transport` setting to avoid premature closure of Messages streams observed with its default aiohttp transport. Runtime, browser SDK and Harness acceptance retries are disabled. `compose.gateway.yml` is an isolated acceptance overlay whose gateway image includes the gateway repository's `tests/console_workflows_e2e_server.py` and `tests/managed_model_budget_proxy.py`. Its business tools and account directory are synthetic. It is not a production migration configuration

For the real business connection, add `compose.business.yml` after the two existing compose files. Supply the required business mount directories and network in the private deployment environment. The overlay launches the actual gateway module, reads the existing business directory snapshot and uses the shared policy and governed-account stores. Changes to business permissions affect that shared store; existing grants are not automatically expanded. Keep console sessions, native model data and model credential delivery isolated. Preserve the production subject signing and account encryption keys, and reconcile the existing real user's native key ownership before enabling the entry. See the gateway repository's `docs/litellm-managed-gateway.md` for acceptance and failure behavior

Existing MCP and OAuth routes remain on their prior backend. Validate Nginx before a reload, preserve the bind-mounted configuration inode, and retain a hash-checked route rollback.
